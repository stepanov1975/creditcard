# ccparser v0.2.0

`v0.2.0` adds explicit merchant output and improves source-grounded field ownership
and statement identity. It is a source release for local Linux execution with
Python 3.13 and Tesseract English/Hebrew data.

## Changes since v0.1.0

- Add a nullable `merchant` JSON field and a trailing `merchant` CSV column.
  Extract the complete printed merchant field, including reference codes, URLs
  and owned continuation lines, rather than inferring a shorter business name.
- Preserve wrapped merchant lines, split continuation cells and merchant text
  preceding conversion details. Keep independently positioned ancillary text
  outside the merchant field.
- Concentrate continuation ownership, cross-page detail handoffs and their
  diagnostics in one module while preserving financial interpretation.
- Strengthen source-backed issuer/card identity and recognize Max legal evidence.
  Payment-group charge dates no longer create conflicting statement-date metadata;
  contradictory explicit statement dates still block reconciliation.

## Compatibility and installation

The documented CLI remains the supported interface. Existing JSON keys and CSV
columns remain available; consumers must tolerate unknown JSON keys and trailing
CSV columns. Corrected field ownership can change merchant/description text.
Python module interfaces remain internal. See [SUPPORT.md](../../SUPPORT.md).

Install Tesseract and the supported language data, then install the tagged source:

```bash
sudo apt-get update
sudo apt-get install tesseract-ocr tesseract-ocr-eng tesseract-ocr-heb
python3.13 -m venv .venv
.venv/bin/pip install .
.venv/bin/ccparse --help
```

Parse a statement with:

```bash
.venv/bin/ccparse parse statement.pdf --output-dir output
```

JSON/CSV outputs contain financial data and positioned source evidence; keep them
local and out of version control. No wheel, container or PyPI artifact is published.

## Release verification

Publication requires the exact clean release commit to pass Ruff, mypy, the full
synthetic test suite, clean-source installation and CLI smoke verification, and
protected private-corpus VERIFY. That gate requires 104 retained statements,
104 reconciled results, five quarantined non-statements, exact accepted baseline
parity, deterministic repeated fresh-cache runs, matching toolchain/worker identity
and `performance_checked=true`. The existing protected baseline and membership
remain unchanged; release preparation does not promote a new baseline.

These checks establish regression acceptance, not fresh-document merchant accuracy.
The parser remains conservative on ambiguous evidence and does not promise support
for every issuer or layout. General bank statements are unsupported; non-Linux
platforms are best effort.
